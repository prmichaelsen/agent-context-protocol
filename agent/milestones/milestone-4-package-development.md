# Milestone 4: ACP Package Development System

**Goal**: Implement complete package development workflow with entity creation, validation, and publishing  
**Duration**: 6-8 weeks  
**Dependencies**: Milestone 3 (ACP Package Management System)  
**Status**: Not Started  
**Design Document**: [`agent/design/acp-package-development-system.md`](../design/acp-package-development-system.md)  

---

## Overview

Implement a comprehensive package development system that enables package authors to efficiently create, develop, validate, and publish ACP packages. This milestone extends the package management system (M3) with tools for package creation and maintenance, including entity creation commands, validation with auto-fix, and automated publishing workflows.

---

## Deliverables

### 1. Infrastructure
- YAML schema validation system (pure bash)
- Schema definitions in agent/schemas/
- Namespace detection and validation utilities
- README auto-update utilities
- Pre-commit hook system

### 2. Entity Creation Commands
- @acp.pattern-create - Create patterns with namespace enforcement
- @acp.command-create - Create commands with namespace enforcement
- @acp.design-create - Create design documents with namespace enforcement
- Draft file support with clarification workflow
- Automatic package.yaml and README.md updates

### 3. Validation System
- @acp.package-validate - Comprehensive package validation
- Shell-based validation (structure, files, git)
- LLM-based validation (content quality)
- Auto-fix capabilities with user guidance
- Test installation to verify package works

### 4. Publishing System
- @acp.package-publish - Automated publishing workflow
- Version bump detection (Conventional Commits)
- LLM-based CHANGELOG generation
- Git tag creation
- Post-publish testing

### 5. Enhanced Package Creation
- Rewritten @acp.package-create with full ACP installation
- Release branch configuration
- Pre-commit hook installation
- No example files (use templates)

## Risks & Mitigations

### Risk 1: YAML Schema Validation Complexity
**Risk**: Pure bash YAML schema validation may be complex to implement  

**Mitigation**:
- Start with basic validation (required fields, types)
- Incremental enhancement
- LLM handles complex validation
- Research existing bash YAML validators

### Risk 2: LLM Availability
**Risk**: Some features require LLM (CHANGELOG generation, content validation)  

**Mitigation**:
- Shell validation works without LLM
- Graceful degradation
- Clear separation of LLM vs shell features
- Document LLM requirements

### Risk 3: Git Hook Conflicts
**Risk**: Users may have existing pre-commit hooks  

**Mitigation**:
- Check for existing hooks before installing
- Offer to merge with existing hooks
- Document hook installation
- Provide uninstall instructions

### Risk 4: Namespace Inference Ambiguity
**Risk**: Multiple inference methods may give different results  

**Mitigation**:
- Clear priority order
- Show conflicts and ask user
- package.yaml is source of truth
- Validate inferred namespace

### Risk 5: Scope Creep
**Risk**: Feature requests may expand scope  

**Mitigation**:
- Stick to design document
- Document future enhancements separately
- Focus on core functionality first
- Incremental enhancement in future milestones

## Breaking Changes

### Namespace Requirements
- All package files must use package namespace
- @local namespace reserved for non-packages
- Validation enforces namespace conventions

### @acp.package-create Behavior
- Complete rewrite (no backward compatibility)
- Now installs full ACP in new directory
- No example files created
- Requires release branch configuration

### Validation Separation
- @acp.validate - General ACP validation
- @acp.package-validate - Package-specific validation

## Migration Guide

### For Existing Package Authors

**If you have existing packages created with old @acp.package-create**:

1. **Add Full ACP Structure**:
   ```bash
   cd your-package
   curl -fsSL https://raw.githubusercontent.com/prmichaelsen/agent-context-protocol/mainline/agent/scripts/acp.install.sh | bash
   ```

2. **Add Namespace to Files**:
   - Rename files to include namespace prefix
   - Example: `my-pattern.md` → `firebase.my-pattern.md`

3. **Update package.yaml**:
   - Add release.branch field
   - Update file names in contents section

4. **Run Validation**:
   ```bash
   @acp.package-validate
   ```

5. **Fix Issues**:
   - Follow auto-fix suggestions
   - Or fix manually

6. **Install Pre-Commit Hook**:
   - Hook will be in .git/hooks/pre-commit
   - Or create manually from template
