# Local Artifact Directories Pattern

**Pattern**: Tracked directories with untracked contents for local artifacts
**Version**: 1.0.0
**Created**: 2026-02-22
**Status**: Active

---

## Overview

This pattern establishes a convention for agent directories that should exist in the repository structure but whose contents are primarily local artifacts. These directories use `.gitkeep` files to track the directory itself while `.gitignore` excludes the contents by default, allowing users to explicitly commit specific files when needed.

**Use Case**: Directories like `reports/`, `preferences/`, `feedback/`, `drafts/`, and `clarifications/` contain files that are typically local and temporary, but occasionally contain valuable artifacts worth sharing with the team.

---

## Core Principles

### 1. Directory Exists, Contents Optional

The directory structure is tracked (via `.gitkeep`) so all users have the same directory layout, but contents are untracked by default since they're usually local artifacts.

### 2. Explicit Opt-In for Tracking

Users must explicitly force-add files they want to commit:
```bash
git add -f agent/reports/important-report.md
```

This prevents accidental commits of local artifacts while allowing intentional sharing.

### 3. Consistent Structure Across Projects

All ACP projects have the same directory structure, making it easy to understand where files belong and what to expect.

## Implementation

### Directory Structure

```
agent/
├── reports/          # .gitignored, .gitkeep tracked
│   └── .gitkeep
├── preferences/      # .gitignored, .gitkeep tracked
│   └── .gitkeep
├── feedback/         # .gitignored, .gitkeep tracked
│   └── .gitkeep
├── drafts/           # .gitignored, .gitkeep tracked
│   └── .gitkeep
└── clarifications/   # .gitignored, .gitkeep tracked
    └── .gitkeep
```

### .gitignore Configuration

**File**: `agent/.gitignore`

```gitignore
# Agent Context Protocol - Local Files
# These files are generated locally and should not be committed

# Reports directory - generated by @acp.report command
reports/

# Clarifications directory - local clarification documents
clarifications/

# Feedback directory - local feedback and notes
feedback/

# Drafts directory - work-in-progress drafts
drafts/

# Preferences directory - local preference overrides
preferences/
```

**Note**: Each directory is listed individually (not `reports/*`) so that the directory itself can be tracked via `.gitkeep`.

### .gitkeep Files

Each directory contains a `.gitkeep` file:

```bash
# Create .gitkeep files
touch agent/reports/.gitkeep
touch agent/preferences/.gitkeep
touch agent/feedback/.gitkeep
touch agent/drafts/.gitkeep
touch agent/clarifications/.gitkeep

# Add to git
git add agent/reports/.gitkeep
git add agent/preferences/.gitkeep
git add agent/feedback/.gitkeep
git add agent/drafts/.gitkeep
git add agent/clarifications/.gitkeep
```

### Explicit Tracking

When a file should be committed:

```bash
# Force add specific file
git add -f agent/reports/milestone-1-completion-report.md

# Or use interactive staging
git add -i
```

## Directory Categories

### 1. Reports (`agent/reports/`)

**Purpose**: Session reports and project status summaries generated by `@acp.report`

**Typical Contents**:
- `report-YYYY-MM-DD.md` - Daily session reports
- `report-YYYY-MM-DD-session-N.md` - Multiple sessions per day
- `milestone-N-completion-report.md` - Milestone summaries

**When to Commit**:
- ✅ Milestone completion reports (valuable for project history)
- ✅ Major session reports with significant decisions
- ❌ Daily routine reports (local only)

### 2. Preferences (`agent/preferences/`)

**Purpose**: Preference configurations at project, workspace, or user level

**Typical Contents**:
- `acp.default.yaml` - Project-level ACP preferences
- `{package}.default.yaml` - Package preferences
- `acp.{preset-name}.yaml` - Preset configurations

**When to Commit**:
- ✅ Project-level defaults (team standards)
- ✅ Preset configurations (shared workflows)
- ❌ Personal preference overrides (local only)

**Note**: `acp.default.yaml` is force-added in the ACP repository as a template example.

### 3. Feedback (`agent/feedback/`)

**Purpose**: User feedback, notes, and suggestions for improvements

**Typical Contents**:
- `{feature}.feedback.md` - Feedback on specific features
- `session-notes.md` - Session-specific notes
- `improvements.md` - Improvement suggestions

**When to Commit**:
- ✅ Structured feedback that informs design decisions
- ✅ Important notes that affect project direction
- ❌ Personal notes and reminders (local only)

### 4. Drafts (`agent/drafts/`)

**Purpose**: Work-in-progress drafts for requirements, designs, and planning

**Typical Contents**:
- `{feature}-requirements.draft.md` - Requirements drafts
- `{feature}-design.draft.md` - Design drafts
- `requirements.draft.template.md` - Draft templates

**When to Commit**:
- ✅ Draft templates (reusable structures)
- ✅ Collaborative drafts (team input needed)
- ❌ Personal work-in-progress drafts (local only)

### 5. Clarifications (`agent/clarifications/`)

**Purpose**: Clarification documents for ambiguous requirements or designs

**Typical Contents**:
- `clarification-{N}-{topic}.md` - Numbered clarifications
- Questions and answers for unclear requirements

**When to Commit**:
- ✅ Clarifications that document important decisions
- ✅ Q&A that provides valuable context
- ❌ Routine clarifications (local only)

## Benefits

### 1. Clean Repository
- No accidental commits of local artifacts
- Repository contains only intentional, valuable files
- Reduces noise in git history

### 2. Consistent Structure
- All projects have same directory layout
- Easy to find files (everyone knows where reports go)
- Predictable organization

### 3. Flexible Sharing
- Can share specific artifacts when valuable
- No friction for local-only work
- Explicit opt-in prevents mistakes

### 4. Team Collaboration
- Team members can share important reports
- Preset configurations can be committed
- Feedback can be tracked when relevant

## Anti-Patterns

### ❌ Don't: Commit All Local Artifacts

```bash
# BAD: Commits everything, including local artifacts
git add agent/reports/*
git add agent/preferences/*
```

**Why**: Pollutes repository with personal, temporary files that aren't valuable to the team.

### ❌ Don't: Remove .gitkeep Files

```bash
# BAD: Removes directory tracking
rm agent/reports/.gitkeep
```

**Why**: Directory won't exist for other users, breaking the expected structure.

### ❌ Don't: Modify .gitignore to Track Everything

```gitignore
# BAD: Defeats the purpose of local artifacts
# reports/
# preferences/
```

**Why**: Forces everyone to commit local artifacts or constantly have dirty working directory.

## Usage Examples

### Example 1: Committing a Milestone Report

```bash
# Generate milestone completion report
@acp.report

# Report created: agent/reports/milestone-3-completion.md

# This report is valuable for project history - commit it
git add -f agent/reports/milestone-3-completion.md
git commit -m "docs: add milestone 3 completion report"
```

### Example 2: Sharing a Preset Configuration

```bash
# Create preset for team workflow
# File: agent/preferences/acp.team-workflow.yaml

# This preset should be shared with team
git add -f agent/preferences/acp.team-workflow.yaml
git commit -m "feat: add team workflow preset"
```

### Example 3: Keeping Feedback Local

```bash
# Create feedback file
# File: agent/feedback/personal-notes.md

# This is personal - don't commit
# File stays local, .gitignore prevents accidental commit
```

### Example 4: Committing Important Clarification

```bash
# Clarification documents important architectural decision
# File: agent/clarifications/clarification-5-auth-strategy.md

# This clarification is valuable - commit it
git add -f agent/clarifications/clarification-5-auth-strategy.md
git commit -m "docs: add auth strategy clarification"
```

## Setup Instructions

### For New Projects

When installing ACP, the directories are created automatically:

```bash
# ACP installation creates:
agent/reports/.gitkeep
agent/preferences/.gitkeep
agent/feedback/.gitkeep
agent/drafts/.gitkeep
agent/clarifications/.gitkeep

# And adds to agent/.gitignore:
reports/
preferences/
feedback/
drafts/
clarifications/
```

### For Existing Projects

Add the pattern manually:

```bash
# Create directories with .gitkeep
mkdir -p agent/{reports,preferences,feedback,drafts,clarifications}
touch agent/reports/.gitkeep
touch agent/preferences/.gitkeep
touch agent/feedback/.gitkeep
touch agent/drafts/.gitkeep
touch agent/clarifications/.gitkeep

# Update agent/.gitignore
cat >> agent/.gitignore << 'EOF'

# Local artifact directories
reports/
preferences/
feedback/
drafts/
clarifications/
EOF

# Commit structure
git add agent/*/.gitkeep agent/.gitignore
git commit -m "feat: add local artifact directories pattern"
```

## Decision Tree

```
Should this file be committed?
├─ Is it a template or example?
│  └─ Yes → Commit it (valuable for all users)
├─ Does it document an important decision?
│  └─ Yes → Commit it (valuable for project history)
├─ Is it a team standard or preset?
│  └─ Yes → Commit it (valuable for team consistency)
├─ Is it personal notes or work-in-progress?
│  └─ Yes → Keep local (not valuable to others)
└─ When in doubt → Keep local (can always commit later)
```

## Related Patterns

- **Template Pattern**: Templates are committed, instances are local

## Notes

- `.gitkeep` files are empty - their only purpose is to track the directory
- Users can always force-add files with `git add -f`
- This pattern balances structure (directories exist) with flexibility (contents optional)
- Particularly useful for agent-generated content that varies by user
- Prevents repository pollution while enabling selective sharing
